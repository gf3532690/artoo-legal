# Agent Note: 手动维护文档效力状态

Status: implemented

## Problem

`validity_status` 只在解析完成时由管道写入一次，来源是数据源自己的字典——它权威，但既不完整也
不总是对的。全语料里 `0` 未标注 覆盖 2,031 份文档，它们的源文件根本没标；而抽取能做到多好，
取决于它读到的 `docProps`。此前没有任何办法纠正一个值：文件列表、
[法条库文件列表带效力状态并可筛选](2026-09-15-legal-document-validity-status-filter.zh.md)
加的那排状态标签、以及召回默认"排除已废止"的规则，全都依赖一个用户看得出错、却碰不了的字段。

## Decision

新增 `PATCH /api/documents/{doc_id}/validity-status`，请求体 `{"validity_status": <六个取值之一>}`；
文件上右键出现「更新状态」，弹窗选一个值。

- **两处一起写。** `documents.validity_status` 是文件列表展示与筛选读的；每个子块的
  `metadata.validity_status` 是检索水合进 `results[].metadata`、以及默认排除规则读的。
  只写一处，同一份文档会同时处于两种状态。
- **只认字典里的六个取值。** 别的整数一律 400。字典外的值在列表里渲染成「取值 N」，而且没有
  任何筛选项能选中它——收下它就等于造出一行谁也找不回来的记录。
- **只允许已解析完成的文档。** 未解析完的文档没有子块，只改列会造出一个检索侧看不见的状态。
- **与"重新识别"同一道写权限闸门**：`_authorize_kb_access(WRITE)`。改状态就是改内容。
- **清检索结果缓存**（本地 + 跨进程广播）。否则下一次检索命中的还是带旧状态的缓存，这次修改
  看起来像没生效。
- **重新解析会覆盖它。** 这是记录下来的取舍而不是被工程手段绕开：手动维护的含义是"把抽取错的
  改对"，不是"给这条文档钉一个永久属性"。
- 顺带补上列表视图缺的「效力状态」列：筛选对两种视图都生效，可原来只有网格视图能看到自己选
  的是什么。

## Alternatives considered

**只更新 `documents.validity_status`。** 否决：写起来更省，页面看着也对——但同一份文档在每一条
检索结果里仍是旧状态，把已废止的法条标成现行有效（或反过来）完全不会改变召回。两个存储的读方
不同，只服务其一的写入路径就是 bug 制造机。

**只更新子块元数据。** 否决：文件列表与它的筛选读的是那一列。

**改完重新解析一遍。** 否决：改一个整数要花几分钟，而且它会重跑抽取——把用户正在覆盖的那个值
再算回来。

**接受任意整数，交给界面原样渲染。** 否决：见上面"只认六个取值"那条。

**加一个 override 标记，让之后的重新解析保留手改值。** 暂缓而非否决。如果手改值将来真的需要
扛过重建索引，那才是正确答案；但它会引入第三种状态（手动 / 抽取 / 未知）以及配套的"恢复自动"
操作。那是一个比本次更大的决定，等真有人因为重建丢过手改值再取用不迟。

## Consequences

这个端点是一个小事务：更新列 → 把键并进每个子块的 metadata（该列是 `json`，合并要经 `jsonb`
往返一次）→ 提交 → 失效缓存。提交前失败就什么都没写。

手改值**与抽取值无法区分**：`meta_source` 记录的是*身份字段*的来源，没有任何地方记录"这是人改
的"。排查一个反常取值时只能问人。

## Verification

`tests/test_legal_document_status_filter.py`（新增 4 项）钉住：两处都被写入、闸门是 WRITE 权限、
字典外的取值被拒且不留任何改动、未解析完成的文档被拒。

本地栈实测，用真实语料文档《宁夏回族自治区执行〈中华人民共和国婚姻法〉的补充规定》
（`validity_status = 1`，10 个子块）：

```text
改动前    documents.validity_status = 1      带 metadata 1 的子块 = 10
          查「宁夏…结婚年龄」默认口径 → 该文档未返回，filtered_invalid_count = 10
PATCH 3
改动后    documents.validity_status = 3      带 metadata 3 的子块 = 10
          同一查询、同一默认口径 → 该文档被返回，
          results[].metadata.validity_status = 3，filtered_invalid_count = 0
还原      PATCH 1 → 列与 10 个子块都回到 1
PATCH 99  → 400「效力状态取值不在数据源字典里（可选：3 现行有效 / …）」
```
